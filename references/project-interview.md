# 每次工程的 grill-me 定制流程

## 触发与工具

用户要求每次工程通过多轮 grill-me 定制方案。新工程、重大重设计必须执行；续作先读取此前决策，只补问发生变化或尚未决定的部分，不从头重复。

优先使用环境中已安装的 grill-me 与 grilling 技能；实际执行时读取可用版本，其他环境先发现技能路径。若未安装，按本文件的同等问答流程执行并说明，不声称已调用不存在的工具或技能。

## 访谈规则

- 普通聊天，一次提出一个影响当前设计分支的关键问题，给出推荐答案、依据与主要取舍，等用户回答后再进入下一问题。
- 不把刚提出的建议自动当作通过。无回复则保留待定，不自动跨越方案或布局审核。
- 尽量用参考图片、具体器件、尺寸证据辅助用户判断，而非连续问无依据的抽象“是否同意”。默认值是候选，不是事实。
- 能从已有工程、器件手册、源项目、购买页面或图片确认的问题，先自行查证；不要求用户重复抄资料。
- 用户主动提供的信息直接纳入决策记录，不重复询问。发现相互矛盾的答案，针对冲突给出明确问题和影响。
- 用户明确要求一次问完时合并当下剩余项；不要把本次通用规则访谈的“最后一轮”理解为以后禁止多轮访谈。

## 按依赖推进，不固定轮数

1. 先获得足以检索的用途、主要功能与目标产品形态；已知的不要再问。
2. 尽早搜索约 5 个相似立创开源项目，获取并查看参考图，再问需要取舍的方案问题。不要在调研前凭想象定下主控和板尺寸。
3. 依次解决影响最大的决策：功能/协议、供电与负载、接口和外壳、主控/连接器采购、制造装配与预算。
4. 再用候选器件的实际尺寸、接口方向及参考证据推导尺寸与正反面安排，确定关键网络约束和验收方式。
5. 每个回答更新本工程决策记录，并同步选型、功能图和方案的受影响部分。不因一次“y”跳过后续必要问题。

具体问题示例：

- “这次上游使用固定线缆还是可插拔接口？推荐……，原因是……，对外壳和BOM的影响是……。”
- “当前主选可用较大的可手焊封装，备选更小但需要贴片。根据预算和装配要求推荐……，你选哪种？”
- “已核实接口外形后，候选尺寸为……，另一尺寸需要改变……。推荐……，是否按这个方向做方案？”

以上是提问形式，不是 USB 项目或尺寸的通用固定要求。

## 决策记录

在工程的审核目录中记录需求与决策；文件名可采用 `REQUIREMENTS.md`、`DECISIONS.md`，避免在 skill 自身目录写具体工程状态。

每项包含：问题、用户答案、推荐及依据、确认状态、相关来源、影响到的器件/尺寸/文档、未决依赖。区分“用户选择”“资料已验证”“推导值”“尚未核实”。

## 收敛与两次审核

当主要功能、供电、接口/结构、器件采购、制造条件和验收目标清楚，且不存在阻止方案形成的关键矛盾，即停止继续扩展问题，生成第一次审核包。

第一次审批针对具体材料版本；访谈答案不能替代最终方案确认。第一次通过后落实原理图与 PCB 布局，再以正反面和 3D 进行第二次审核；通过后连续完成布线铺铜与验收。

若参考数量、采购链接、模型或结构尺寸存在关键缺口，明确提交缺口及可推进项；不能因为访谈次数很多就视为方案已完整。
